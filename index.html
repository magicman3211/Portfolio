Azure IAM – Joiner, Mover, Leaver (JML)

Identity and Access Management lifecycle processes in Microsoft Entra ID (Azure AD)

Overview

This page documents a practical Joiner, Mover, Leaver (JML) process implemented using Microsoft Entra ID (Azure AD), Azure AD Groups, Conditional Access, and optionally Azure AD Privileged Identity Management (PIM) and automation tools.

Goal: ensure users have the right access at the right time, with minimal manual effort and strong auditability.

Joiner Process

Trigger

  • New hire record created in HR system
  • Start date and role confirmed

Key Steps

  • User account provisioned in Entra ID (manually or via HR-driven provisioning)
  • Assigned to base role-based groups (e.g. “All Employees”, “Melbourne-Office”)
  • Licensed (Microsoft 365, Intune, etc.) according to role
  • Added to application-specific groups as required (e.g. “Sales-Apps”, “IT-Admins-L1”)
  • Conditional Access policies apply automatically based on group membership

Automation Options

  • Entra ID Provisioning with HR system (Workday, SuccessFactors, etc.)
  • PowerShell / Graph API scripts for group assignment
  • Logic Apps / Power Automate flows triggered by HR events

Mover Process

Trigger

  • Role change, department move, location change, or promotion

Key Steps

  • Update user attributes in Entra ID (department, jobTitle, office, manager, etc.)
  • Remove from old role-based groups that no longer apply
  • Add to new role-based and application groups for the new position
  • Review and adjust Conditional Access and PIM eligibility if access level changes
  • Log changes for audit and compliance

Automation Options

  • Dynamic groups based on attributes (department, jobTitle, etc.)
  • Graph API / PowerShell scripts to reconcile group membership
  • Periodic access reviews in Entra ID to validate movers’ access

Leaver Process

Trigger

  • Termination, resignation, contractor end-date, or account disable request

Key Steps

  • Disable or block sign-in for the user in Entra ID
  • Revoke active sessions and refresh tokens
  • Remove from all security and Microsoft 365 groups
  • Remove from all application assignments and PIM roles
  • Convert mailbox to shared (if required) and handle data retention
  • Archive or transfer OneDrive / Teams data per policy
  • Log all actions and retain evidence for audit

Automation Options

  • HR-driven deprovisioning via Entra ID Provisioning
  • Logic Apps / Power Automate flows triggered by HR termination events
  • PowerShell / Graph scripts to standardise leaver cleanup

Security & Governance

  • Principle of least privilege applied via role-based groups
  • Conditional Access policies enforce MFA, device compliance, and location rules
  • PIM used for just-in-time admin access where appropriate
  • Regular access reviews for sensitive groups and applications
  • Audit logs in Entra ID and connected systems for all JML actions
